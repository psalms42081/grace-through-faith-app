Final polish pass + Great Controversy Timeline Engine

We are not adding random new features. This pass is for cohesion, consistency, and one major flagship study experience.

GOAL
Make the app feel like one unified learning platform across Devotional Plans, Study Paths, Fundamental Beliefs, Prophecy Explorer, Bible Reader, and Guided Study. Then build a Great Controversy Timeline Engine that connects doctrine, prophecy, Scripture, and history in a distinctly Adventist but accessible way.

IMPORTANT
- Preserve existing navigation and architecture unless needed for consistency
- Do not break current working flows
- Keep dark theme, typography, spacing rhythm, and current visual language
- Make changes production-ready, not placeholder/demo quality
- Test all touched flows
- No fabricated quotes
- Scripture remains primary authority
- Adventist framing should be clear but not cluttered or preachy
- Avoid dense walls of text; prioritize structured learning UX

====================================
PHASE 1 — FINAL CONSISTENCY / POLISH PASS
====================================

T001 — Standardize Progress States Across Learning Surfaces

Audit and unify progress UI across:
- Devotional Plans
- Study Paths
- Guided / Inductive Study
- Fundamental Beliefs
- Prophecy Explorer intro + timelines where applicable

Every learning surface should support a consistent state model where relevant:
- Not started
- In progress
- Completed

Implement shared visual language:
- In progress: accent/gold treatment with “Continue”
- Completed: green check badge / completed label
- Not started: neutral / default state

Specific expectations:
- Devotional plans already show progress; keep and refine
- Study Paths already show module progress; keep and refine
- Fundamental Beliefs should clearly indicate viewed/completed belief items if tracked
- Prophecy intro modules should support viewed/completed state if user opens them
- Guided Study sessions should clearly show resume vs completed states

Do not overdecorate. Keep it subtle and consistent.

T002 — Standardize Scripture Reference Interaction

Across the app, every tappable Scripture reference should route consistently into the Bible reader with verse highlighting when possible.

Audit these areas:
- Fundamental Beliefs key scriptures
- Prophecy Explorer references
- Devotional plan day scriptures
- Study path modules
- Verse Map cross references
- Any other study cards or doctrine cards with references

Requirements:
- Use one shared helper/parser for scripture navigation
- Open the correct book/chapter
- When verse range is available, highlight the starting verse and preserve context
- Maintain navigation stack so back returns to the prior screen, not Home
- Reader highlight treatment should match existing soft gold highlight and fade behavior

T003 — Content Hierarchy Consistency

Review and normalize content structure across these feature types:
- Devotional day screen
- Guided Study screen
- Fundamental Belief expanded card
- Prophecy topic detail
- Verse Map section details
- Insight & Voices cards

Where appropriate, content should follow this general order:
1. Scripture
2. Explanation / context
3. Reflection / meaning
4. Application / next step

Do NOT force identical templates everywhere, but remove any screens that feel unordered or harder to scan than others.

T004 — Shared Section Header / Meta Row Consistency

Normalize micro-UI patterns across the app:
- Section headers
- Subtitles
- Meta rows (days, minutes, difficulty, modules, weeks)
- Card footers
- Empty states
- Continue labels
- Completed labels

Examples:
- If one area says “~15 min” and another says “15m”, standardize
- If some sections use all caps labels and others sentence case, normalize thoughtfully
- Make sure difficulty chips are visually consistent everywhere

T005 — Learning Completion Feedback

Create subtle completion feedback patterns across learning screens:
- When a devotional is finished, show a small success state
- When a path module is completed, show a completion treatment
- When a belief is fully reviewed, show confirmation
- When prophecy intro cards are all viewed, reflect that in UI
- Guided Study completion already exists; refine visual consistency only if needed

Avoid celebratory gamification that feels childish. This is spiritual formation, not arcade UI.

T006 — Navigation Regression Test Pass

Test and fix any broken or inconsistent back-stack behavior for:
- Reader -> Verse Actions -> Word Study -> Back -> Reader
- Reader -> Verse Actions -> Insight -> Back -> Reader
- Reader -> Verse Actions -> Verse Map -> Back -> Reader
- Verse Map -> Study This Verse -> Inductive Study -> Back -> Verse Map
- Study tab -> Fundamental Beliefs -> Scripture -> Reader -> Back -> Beliefs
- Study tab -> Prophecy Explorer -> Topic -> Scripture -> Reader -> Back -> Topic
- Study tab -> Devotional Plans -> Plan -> Day -> Scripture -> Reader -> Back -> Day

No unexpected jumps to Home.
No duplicate routes.
No dead-end screens.

====================================
PHASE 2 — GREAT CONTROVERSY TIMELINE ENGINE
====================================

This should become a flagship feature of the Study area.

CORE IDEA
Build an interactive Great Controversy Timeline Engine that helps users understand the broad biblical conflict theme from:
- Creation
- Fall
- Covenant history
- Cross
- Early church
- Daniel
- Revelation
- Sanctuary
- Judgment
- Second Coming
- Millennium
- New Earth

This should connect:
- Scripture
- Prophetic milestones
- Historical fulfillments
- Adventist themes
- Fundamental beliefs
- EGW secondary reading links where appropriate

This must feel educational, structured, and visually clear.

T007 — Add “Great Controversy Timeline” as a Flagship Study Surface

Create a dedicated screen/flow accessible from:
- Study tab
- Study Paths area
- Possibly Prophecy Explorer header/CTA if appropriate

Screen title:
- Great Controversy Timeline

Subtitle:
- Trace the conflict between Christ and Satan through Scripture, history, prophecy, and redemption

This screen should not just be a long article.
It must be interactive and modular.

T008 — Timeline Overview UI

At the top of the engine, create a horizontal / segmented timeline overview with the major eras:

Suggested phases:
- Creation
- Fall
- Patriarchs & Covenant
- Israel & Kingdom
- Christ’s Ministry
- Early Church
- Daniel’s Visions
- Revelation & Remnant
- Judgment & Second Coming
- Millennium
- New Earth

Requirements:
- Each phase is tappable
- Active phase is visually clear
- Users can move linearly or jump between phases
- Smooth scroll or snap behavior is welcome
- Keep it readable on mobile

T009 — Phase Detail Cards

Each phase should open/render a structured learning view with these sections where relevant:
- Big idea summary (2–4 sentences)
- Key Scriptures
- Why this matters in the Great Controversy theme
- Historical / prophetic significance
- Connected beliefs
- Related study modules / next steps

Example for “Creation”:
- God creates a good world
- Moral order begins with God’s character and government
- Conflict has not yet entered
- Connect to Creation, Sabbath, Nature of Humanity beliefs

Example for “Judgment & Second Coming”:
- Investigative judgment / heavenly ministry context
- Christ’s return
- Vindication of God’s character and people
- Connect to sanctuary, second coming, end-time beliefs

T010 — Scripture, Belief, and Prophecy Linking

Within each timeline phase, support deep linking to:
- Bible reader passages
- Relevant Fundamental Beliefs cards
- Relevant Prophecy Explorer modules
- Relevant Devotional Plans or Study Paths if available

Examples:
- Daniel phase links into Daniel 2, 7, 8–9
- Revelation phase links into Three Angels, Sanctuary, Mark of the Beast, Second Coming
- Christ phase links into Gospels and salvation beliefs
- New Earth phase links into Revelation 21–22 and New Earth belief

All links must preserve navigation stack properly.

T011 — Add a Visual Legend

Create a compact legend near the top of the timeline engine so users understand categories/colors.

Suggested legend categories:
- Scripture
- History
- Prophecy
- Belief
- Fulfillment
- Hope / Restoration

The exact colors can match existing palette, but keep them subtle and readable in dark mode.

This legend is important. Users should immediately understand the logic of the timeline.

T012 — “Conflict Thread” Summaries

For each major phase, include a concise “Conflict Thread” panel that explains how that moment advances the larger controversy theme.

Examples:
- Fall: rebellion, deception, broken trust
- Cross: decisive revelation of God’s character and Satan’s methods
- Daniel: kingdoms of men vs kingdom of God
- Remnant / final crisis: worship, loyalty, endurance
- New Earth: final restoration and end of sin

These should be short, clear, and theologically responsible.

T013 — Adventist Framing Without Overload

This engine should be distinctly Adventist, but not overwhelming to newcomers.

Requirements:
- Use Adventist themes where appropriate
- Avoid assuming prior theological background
- Use clear explanatory language
- Keep Scripture primary
- EGW should be secondary, optional, and visually subordinate

If EGW links are included:
- Label them clearly
- Keep them as optional “Read more in Ellen G. White Writings”
- Do not fabricate quotes
- Do not overfill the timeline with EGW content

T014 — Add “Next Step” CTAs Per Phase

Each timeline phase should help the user continue learning.

Possible CTA patterns:
- Read the key passage
- Explore related prophecy
- Open related belief
- Start a devotional
- Begin a guided study on this theme

This turns the timeline into a hub, not just a reference screen.

T015 — Progress Tracking for Timeline Phases

Track user interaction with timeline phases:
- viewed
- completed (if user meaningfully opens/expands/interacts with all key content in that phase)
- last viewed phase

Show subtle progress UI such as:
- phase dots/checks
- completed state
- “Continue Timeline” entry point if the user leaves and comes back

Persist progress locally and/or through existing user progress model if appropriate.

T016 — Mobile Readability and Interaction

Optimize specifically for mobile:
- No cramped horizontal text
- No tiny tap targets
- No overly long unbroken cards
- Good spacing between eras and cards
- Sticky or easy-to-access phase navigator if helpful
- Ensure chip rows / phase tabs don’t feel cut off or awkward

T017 — Content Integrity Guardrails

All generated or structured educational content in this engine must:
- prioritize Scripture
- avoid speculative theology beyond intended Adventist doctrinal framing
- distinguish historical fulfillment from interpretive summary where necessary
- not fabricate historical facts or quotations
- stay concise and educational

T018 — Final QA / Test Pass

Test these flows:
- Study -> Great Controversy Timeline -> open a phase -> open Scripture -> back
- Timeline -> open linked belief -> back to timeline
- Timeline -> open linked prophecy section -> back to timeline
- Leave the timeline midway -> return -> continue where user left off
- Progress indicators persist correctly
- No layout breakage on small Android screens
- No clipped text in chips, cards, or timeline labels

====================================
DESIGN / TONE GUIDANCE
====================================

Use these principles:
- Reverent
- Clear
- Structured
- Educational
- Warm but not fluffy
- Adventist identity should feel confident, not defensive
- Avoid neon or bright distracting colors
- Keep existing premium dark aesthetic
