The Adventist Spiritual Formation System
A complete product blueprint for a defining SDA formation platform (built on Replit with Expo + Express + Postgres).
0) Product Definition
Mission
Build the first premium, SDA-dedicated formation system that helps a person become (and remain) a mature disciple through structured Adventist identity formation—not content consumption.
Category Statement
Most apps distribute information. This platform builds a person.
Target Outcome
A user should measurably grow in:
Biblical literacy (Text)
Adventist theological clarity (Doctrine)
Prophetic competency (Prophecy / historicism)
Sabbath rhythm and culture (Sabbath Formation)
Character + spiritual disciplines (Practice)
Family discipleship (Home)
Mission orientation (Witness)
Core Promise
Guided progression + daily rhythm + weekly Sabbath formation + mastery pathways.
1) Product Pillars
Pillar A — Formation Pathways (structured progression)
A sequenced “curriculum” with stages, lessons, practices, assessments, and milestones.
Pillar B — Sabbath School Integration (weekly engine)
Not PDFs. A structured weekly journey with layers, group mode, teacher mode, and family prompts.
Pillar C — Prophecy Academy (mastery engine)
Interactive training: timelines, symbol maps, historicist reasoning, and assessments.
Pillar D — Family Sabbath Formation (Friday sunset → Saturday sunset)
A guided Sabbath liturgy & family discipleship mode with age-aware flows.
Pillar E — Spiritual Disciplines & Character (habit engine)
Practice loops: prayer, Scripture meditation, service, temperance, rest, confession, etc.
Pillar F — Deep Study Tooling (serious study UX)
Text → context → doctrine → prophecy links → application, with notes and exports.
Pillar G — Progress & Identity Metrics (formation analytics)
Track what matters: consistency, mastery, practice completion, and reflection depth.

5.2 Lesson Template (Standardized)
Every lesson (doctrine/prophecy/discipline) uses a consistent “formation schema”:
Anchor Text (primary Scripture)
Observe (what it says)
Explain (what it means)
Integrate (how Adventism understands it)
Challenge (common objections / confusion points)
Practice (one concrete action)
Reflect (journal prompt)
Assess (2–6 questions)
Memory (optional verse)

11) Experience Design Principles
Reverent, calm premium UI (not loud gamification)
Progression is clear (always shows next step)
Frictionless daily loop (start in 1 tap)
Sabbath Mode reduces noise (less UI clutter)
Family-first design (tiered prompts)
Explain without being combative (prophecy especially)
12) Content Governance & Integrity
Theological posture
Faithful to SDA historic positions (don’t editorialize aggressively)
Use Scripture-first explanations
Include “how to talk about this graciously” prompts
Copyright safety
Don’t embed copyrighted commentaries.
Create original explanations.
Link out to official/public-domain sources where appropriate.

16) “Defining” Differentiators (Non-Negotiables)
If these are present, you’re not “another Bible app”:
Progression (you’re forming a person, not showing a library)
Prophecy mastery tools (interactive, not PDF-based)
Sabbath formation mode (ritual + rhythm + family)
Weekly Sabbath School engine (layered, structured, discussion-first)
Disciplines + practice (action loop)
17) Technical Notes for Replit Implementation
Keep content as seedable JSON → write importer → store in Postgres
Version your content (content_version table) for safe updates
Keep “today plan” generation on server (rules-based) for consistency
Cache content on device (AsyncStorage + lightweight local index)
Make the app usable with limited internet (Sabbath Mode especially)
18) Acceptance Criteria (When v1 is “real”)
v1 is ready when:
A new user can onboard in 2 minutes
They get a daily plan instantly
They can complete a lesson + practice + reflection in <15 minutes
They can prepare for Sabbath School through the week
They can run a Sabbath discussion using the app
They can complete Daniel 2 and explain it back simply
Their progress and next steps are always clear
