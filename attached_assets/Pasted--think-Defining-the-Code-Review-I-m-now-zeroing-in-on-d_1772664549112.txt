### 🏗️ Architecture & Maintainability

**1. The Monoliths (`server/routes.ts` & `app/read/[bookId]/[chapter].tsx`)**
As you noted, these files are massive. 
*   **Backend:** A 2,100+ line `routes.ts` file will become a nightmare for merge conflicts and debugging. 
    *   *Recommendation:* Use Express `Router`. Create a `server/routes/` folder with `bible.ts`, `study.ts`, `kids.ts`, `user.ts`, etc. Mount them in `index.ts` like `app.use('/api/kids', kidsRoutes)`.
*   **Frontend:** The chapter reader file does too much. It handles UI rendering, database fetching, TTS state, audio player lifecycles, and layout calculations.
    *   *Recommendation:* Extract the audio logic into a custom hook: `const { play, pause, stop, isPlaying, ... } = useBibleAudio(verses, ...);`. Extract the `ContextPanel` and `RelatedContent` into their own separate files in a `components/` directory.

**2. Hardcoded Data in Components**
Files like `app/family.tsx`, `app/music.tsx`, and `app/topic/[id].tsx` contain hundreds of lines of hardcoded arrays.
*   *Recommendation:* Move this data out of the component files. Either put them in `constants/data.ts` or, ideally, move them into your PostgreSQL database so you can update featured sermons, music, or topics without having to push an app update to the App Store/Google Play.

**3. Separation of Concerns in AI Prompts**
In `routes.ts`, your AI system prompts are hardcoded directly inside the route handlers.
*   *Recommendation:* Create a `server/services/ai.ts` or `server/prompts.ts` file to manage these. This makes it much easier to tweak and version-control your prompts without touching the routing logic.

### ⚡ Performance

**1. Rendering Large Chapters**
In `app/read/[bookId]/[chapter].tsx`, you render verses by mapping over them inside a `<Text>` component:
```tsx
<Text style={styles.proseText}>
  {verses.map((v, i) => ( ... ))}
</Text>
```
While this is the correct way to achieve continuous, inline prose in React Native, it can cause severe memory and layout calculation issues for massive chapters (like Psalm 119). 
*   *Recommendation:* Keep an eye on performance here. If you notice UI freezing on load, you may need to implement a chunking strategy or use a `FlatList` (though `FlatList` breaks continuous inline prose wrap). Alternatively, memoize the rendered text block.

**2. Image Rendering**
You are currently using React Native's built-in `<Image>` component.
*   *Recommendation:* Switch to `expo-image` (`import { Image } from 'expo-image'`). It is significantly more performant, handles aggressive disk caching, and supports blurhashes/placeholders, which will make screens like `kids-stories.tsx` and `explore.tsx` feel much snappier.

### 🔒 Security & Edge Cases

**1. AI Endpoint Vulnerabilities**
Your `/api/study-guide/start` and `/api/context/generate` endpoints take user input and pass it to OpenAI. 
*   *Recommendation:* Implement strict rate-limiting (e.g., `express-rate-limit`) on all `/api/*/generate` routes. Without authentication or rate limiting, a malicious actor could spam these endpoints and drain your OpenAI credits.

**2. Input Validation**
While you have Zod schemas defined in `schema.ts` (e.g., `insertUserSchema`), your API routes currently rely on manual `if (!req.body.id) return res.status(400)` checks.
*   *Recommendation:* Use Zod to validate all incoming API payloads. It will automatically strip out unexpected fields and ensure type safety at the boundary layer.

**3. The "Guest" User Debt**
Currently, all user actions (highlights, prayers, streaks) are tied to the string `"guest"`. 
*   *Recommendation:* Before you launch, you must implement a real auth system (Clerk, Supabase, or custom JWT). If you launch with `"guest"`, every user in the world will share the same prayer journal and reading streaks! If you want to allow unauthenticated usage, generate a random UUID on first app launch, store it in `AsyncStorage`, and pass *that* as the `userId`.

### 📝 Code Level Nitpicks

*   **Z-Index & Modals:** In `app/onboarding.tsx` and others, be careful with absolute positioning and z-indexes. You are using `Modal` from `react-native` in several places. Consider using a bottom-sheet library like `@gorhom/bottom-sheet` for a more modern, iOS/Android-native feel for things like the Translation Picker or PIN entry.
*   **Error Handling:** In `routes.ts`, many catch blocks look like this:
    ```typescript

      console.error(err);
      return res.status(500).json({ error: "Internal server error" });
    }
    ```
    Consider passing the actual error message to the frontend in development mode to make debugging easier, and wrapping this in a centralized error-handling middleware.
