# 1. Fix auth foundation

## Files to inspect first

* `server/middleware/auth.ts`
* `server/routes/auth.ts`
* `server/middleware/rate-limit.ts`
* `server/routes/user.ts`

* `server/routes.ts`
* `server/index.ts`
* `contexts/AuthContext.tsx`
* frontend files that append `userId` in query/body for protected endpoints

## Problems to fix

Right now the backend often trusts:

* `req.query.userId`
* `req.body.userId`
* path params like `:userId`

That is not safe for authenticated routes.

## Implement in `server/middleware/auth.ts`

Replace the current loose auth approach with these helpers:

### A. `getAuthUserId(req): string | null`

* Read bearer token from `Authorization`
* Verify JWT
* Return `userId` from token if valid
* Return `null` if no valid token

### B. `requireAuth(req, res, next)`

* Use `getAuthUserId`
* If missing/invalid token, return `401`
* Attach `req.auth = { userId }` or similar typed field
* Continue on success

### C. `optionalAuth(req, res, next)`

* If valid token exists, attach `req.auth.userId`
* Otherwise continue with `req.auth = null`

### D. `getEffectiveUserId(req): string`

* If authenticated, return `req.auth.userId`
* Otherwise return `"guest"`

### E. `requireSelfAccess(candidateUserId, authUserId)`

* Small helper to compare ids for routes where a path param exists
* If mismatch, return false / throw

### F. `checkProStatus`

* It must no longer read `req.query.userId` or `req.body.userId`
* It must only use authenticated user identity
* If unauthenticated, return `401`
* If authenticated but not pro, return `403`

### G. JWT secret handling

Current behavior has a hardcoded fallback secret. Remove that.

Create production-safe behavior:

* if `JWT_SECRET` is missing, server must fail to start
* no hardcoded production fallback secret
* local dev can still use `.env`
